#+TITLE: cl-jobpond
#+STARTUP: content

=cl-jobpond= runs caller-supplied job bodies on a bounded pool of reusable
threads. Every job is supervised: it publishes exactly one terminal result, it
can be cancelled while it runs, it can carry a wall-clock deadline, and it
reports progress to listeners.

#+BEGIN_SRC lisp
(let ((pool (cl-jobpond:make-job-pool :maximum-concurrency 4)))
  (unwind-protect
       (let ((job (cl-jobpond:job-pool-submit
                   pool
                   (lambda (job)
                     (* 2 (cl-jobpond:job-payload job)))
                   :name "double"
                   :payload 21)))
         (getf (cl-jobpond:job-await job) :result))
    (cl-jobpond:job-pool-close pool)))
;; => 42
#+END_SRC

The pool owns admission, concurrency, lifecycle, cancellation, and retention.
The body owns the work.

* Jobs

A job body is a function of one argument, the job itself. Its outcome is typed:

- returning a value publishes =:completed= with that value as the result
- signalling =job-aborted= publishes =:aborted=
- signalling any other error publishes =:failed= with a bounded condition report

A body that escapes even those paths is caught by the worker backstop and
published as =:failed=. A job that has been admitted always becomes terminal.

=job-snapshot= returns a coherent plist of state, result, cancellation reason,
condition report, timings, and progress. Prefer the snapshot when several
fields must agree.

* Admission

=job-pool-submit= admits one job. =job-pool-submit-batch= admits a list of
entry plists atomically: either every entry is queued, or none is.

#+BEGIN_SRC lisp
(cl-jobpond:job-pool-submit-batch
 pool
 (list (list :function #'summarize :payload report-a :name "report-a")
       (list :function #'summarize :payload report-b :name "report-b")))
#+END_SRC

Three bounds are enforced:

- =:maximum-concurrency= limits jobs running at the same time
- =:maximum-batch-size= limits one atomic admission
- =:maximum-live-jobs= limits queued and running jobs together

The last two refuse work with =job-pool-capacity-exceeded=.

A pool starts one worker thread per unit of its concurrency bound at
construction. Pass =:start-threads-p nil= for a pool that starts them on its
first admission. Close a pool with =job-pool-close= when it is no longer
needed.

=job-pool-update-limits= replaces the concurrency, batch-size, live-job, and
default-runtime limits under the pool lock. Every value is required and
validated before any policy changes.

#+BEGIN_SRC lisp
(cl-jobpond:job-pool-update-limits
 pool
 :maximum-concurrency 2
 :maximum-batch-size 4
 :maximum-live-jobs 8
 :maximum-runtime-milliseconds 30000)
#+END_SRC

* Progress

A body calls =job-report-progress= to publish a progress value, append to a
bounded output tail, and advance a step count. =job-progress-snapshot= reads
the result from any thread.

#+BEGIN_SRC lisp
(cl-jobpond:job-report-progress job :detail '(:stage :parsing) :output line)
#+END_SRC

Every progress report is also a cancellation point: it signals =job-aborted=
when a controller asked for cancellation.

* Cancellation

=job-cancel= is first-writer. The first accepted request records its reason;
later requests return =nil=. A queued job leaves the queue and publishes
=:aborted= immediately. A running job is interrupted on its worker thread.

Interrupts are best effort. A body blocked where the host cannot deliver them
stops at its next =job-check-cancellation= or =job-report-progress= call.
=job-aborted= is a =serious-condition=, so a body that handles =error= broadly
lets cancellation through.

* Deadlines

A positive =:maximum-runtime-milliseconds= gives every job of the pool a
wall-clock cap, and an individual entry may override it. A single monitor
thread cancels expired jobs with the reason =:timeout=. Zero disables
deadlines.

* Terminal results

Terminal jobs stay available for inspection through =job-pool-find-job= and
=job-pool-list-jobs=, bounded by =:terminal-retention-limit=. Once the ring is
full the oldest terminal job is evicted, and looking it up afterwards signals
=job-not-found=. The evicted job object itself remains valid for anyone still
holding it.

Publication is single-writer. A host that wants to own what a terminal job
carries supplies =:terminal-result-function=. It is called with the job, the
resolved state, the result being published, and the report, and returns its
own result, report, and state:

#+BEGIN_SRC lisp
(lambda (job state result report)
  (values (list :status state :value result :error report)
          report
          state))
#+END_SRC

The hook runs inside the publication claim and outside the job's lifecycle
lock, so exactly one writer ever runs it. It may take locks or do input and
output.

* Listeners

=job-pool-add-listener= registers a function of a channel keyword and an event
plist. The pool emits:

- =:job-lifecycle= events with the statuses =:started=, =:completed=,
  =:failed=, and =:aborted=
- =:job-progress= events for each report

Every event carries the job it is about as =:job=. A listener that signals is
ignored. Listeners run on the thread that produced the event.

* Shutdown

Wait for the jobs that matter with =job-await= first. Closing is idempotent
and safe from several threads at once. =job-pool-detach= then drops the
runtime state of a closed pool, and =job-pool-refresh= reopens it with fresh
workers.

* Job trees

A job may name its ancestors with =:owner-identifiers=, outermost first, and
the tree it belongs to with =:root-identifier=. =job-pool-descendant-jobs=
finds a whole subtree in one pass. =job-cancel= with =:cascade-p= cancels that
subtree and returns the descendants it took. The job itself is cancelled
first.

* Running a job on a chosen thread

=job-run-inline= runs a queued job on the calling thread, which keeps a pool
from deadlocking when every worker is blocked waiting on another job. A host
that must have a particular thread admits the job with =:inline-only-p=. Such
a job counts against the live bound and is findable and cancellable like any
other, but only =job-run-inline= will ever run it.

* Host fields

A host with fields of its own subclasses =job= and gives the pool =:job-class=;
each admission entry then carries =:initargs= for that class.

* Durable schedules (optional)

Load =cl-jobpond/schedules=. This system supplies a locked portable state machine;
the host supplies execution and a persistent process or event loop.

#+BEGIN_SRC lisp
(let ((scheduler (cl-jobpond:make-scheduler :store #'atomic-save)))
  (cl-jobpond:scheduler-add scheduler :id "daily" :version "v3"
                           :payload '(:task "summarize")
                           :at (get-universal-time) :interval 86400
                           :missed-policy ':latest)
  (cl-jobpond:scheduler-wake scheduler)
  (let ((claim (cl-jobpond:scheduler-claim scheduler :version "v3")))
    (when claim
      ;; Admit CLAIM's payload into the existing execution facility, then settle it.
      (cl-jobpond:scheduler-ack scheduler :id (getf claim :id)
                               :token (getf claim :token) :result '(:proof "done")))))
#+END_SRC

=make-scheduler= accepts =:clock= (default universal time), =:store=, =:snapshot=
and =:capacity= (default 4096). Times use nonnegative integer clock units. IDs
and versions are bounded strings. Registration is immutable and identical
registration is idempotent; use a new ID when replacing a cancelled version.

=scheduler-next-time= returns the earliest active deadline or NIL. Call
=scheduler-wake :now= on a host deadline, and =scheduler-event :event :id :payload=
for an observable event. Stable external event IDs suppress duplicates and reject
changed payloads. Occurrence IDs include schedule ID, version and time/event ID.
Claim with =:id= and/or =:version= to guard stale work.

Missed-run policies are =:all= (every occurrence), =:latest= (coalesce to the most
recent due occurrence), and =:skip= (omit past occurrences, emit one exactly at
NOW). Catch-up capacity failure rolls back the entire wake operation. No terminal
history is evicted implicitly: exhausted retention refuses admission. Capacity
bounds each schedule/wakeup collection.

Claim before external admission. =scheduler-ack :id :token :outcome :result=
settles =:completed=, =:failed= or =:cancelled= and retains host proof. Identical
ACK is idempotent; stale tokens or conflicting outcomes are refused. On reload,
claimed records become =:unknown= and are never automatically reexecuted. Inspect
them, ACK a known outcome, or explicitly authorize =scheduler-resolve :action
:retry= with the existing token. Retry invalidates that token. =:action :unknown=
also records uncertainty in a running host.

=scheduler-cancel :id :version= prevents future/pending work. Claimed outcomes
retain cancellation requests for host settlement. =scheduler-close= closes new
admission and cancels pending work while permitting ACK/inspection.

* Acknowledged mailboxes (optional)

Load =cl-jobpond/mailboxes=. =make-mailbox= accepts =:capacity= (64),
=:history-limit= (4096), =:clock=, =:store= and =:snapshot=. Capacity includes
queued plus every unacknowledged delivery, including unknown recovered outcomes.
Retained history has a separate bound and is never automatically evicted.

#+BEGIN_SRC lisp
(let* ((mailbox (cl-jobpond:make-mailbox))
       (sent (cl-jobpond:mailbox-send mailbox :id "m1" :sender "a" :receiver "b"
                                    :payload '(:text "ready")))
       (delivery (cl-jobpond:mailbox-receive mailbox :receiver "b")))
  (declare (ignore sent))
  (cl-jobpond:mailbox-ack mailbox :id "m1" :receiver "b"
                         :token (getf delivery :token) :result "accepted"))
#+END_SRC

SEND returns the retained message and a second value indicating an identical
duplicate. Changed identity/payload is a conflict, including after acknowledgement.
RECEIVE atomically claims the oldest queued message for its receiver, optionally
restricted by =:id=. Receiver identity and the delivery token are required for ACK.
This library records identity; hosts authorize it before invoking these operations.

=mailbox-find= and =mailbox-snapshot= return isolated records. =mailbox-wait= takes
either =:id= (wait for terminal acknowledgement/cancellation) or =:receiver= (wait
for a queued message without claiming it), plus a real-seconds =:timeout= and
optional =:cancelled-p=. It returns record/state, or NIL and =:timeout=,
=:cancelled= or =:closed=. Waiters use condition notifications; only injected
cancellation predicates require bounded periodic sampling.

Reload converts deliveries to =:unknown=. =mailbox-resolve :id :receiver :token
:action :retry= authorizes redelivery explicitly and invalidates the old token.
=:action :unknown= records uncertainty without redelivery. =mailbox-cancel :id
:sender= terminates queued messages; delivered messages retain their unacknowledged
slot until settlement. =mailbox-close= closes SEND/RECEIVE and cancels queued work.
ACK and identical SEND lookup are available after closure to resolve in-flight work.

* Snapshot persistence

Both optional systems share =cl-jobpond/durable-state= without additional runtime
dependencies. =:store= is a function of one isolated complete version-one snapshot.
It runs under the state lock before visibility and must atomically durably replace
storage, or signal an ordinary ERROR without changing storage. It must not reenter
the same state. Snapshots contain proper lists, strings, rational numbers, keywords,
T and NIL. Data is copied at boundaries; cycles, opaque objects and excessive
nesting/node/string sizes are refused. Read persisted snapshots with =*read-eval*
bound to NIL, and construct a new state with =:snapshot= and the same store.

A nonlocal escape from a store callback may follow publication. That live object
then refuses access with =:uncertain-store=; reload the durable snapshot rather than
repeating an effect against potentially stale state. A power loss after durable
claim likewise recovers as UNKNOWN. Claims/ACKs give explicit at-most-once admission
with uncertain outcomes, not a promise of exactly-once external effects.

Transition failures signal =durable-state-error= with =durable-state-error-reason=
and =durable-state-error-identity=. Expected reasons include =:capacity=,
=:identity-conflict=, =:stale-version=, =:stale-token=, =:outcome-conflict= and
=:closed=. Snapshot format/lifecycle validation precedes recovery and persistence.
